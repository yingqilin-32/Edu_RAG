# V4.1：重排、过滤与证据门控对照

2026-10-19，代码版本 0.4.1。结论：**重排改善排序；回答完成率的主要增益来自分数过滤；生成前门控用于阻止缺依据的问题继续生成或展示题目。** 默认采用重排 + 过滤 + 独立门控。

## 实验设计

固定 114 个 BGE-M3 向量片段、查询计划、每题首次召回的候选池及上下文条数预算。四组采用相同的最终上下文证据门控、生成提示词和生成后核验。第五组只关闭生成前门控，仍保留查询范围检查和生成后核验；该开关只存在于实验脚本，不开放为 API 参数。

| 组别 | 上下文顺序 | 0.75 分数过滤 | 独立证据门控 |
| --- | --- | --- | --- |
| retrieval_order | 原检索顺序（混合检索时为 RRF） | 无 | 有 |
| llm_rerank | 模型评分降序 | 无 | 有 |
| score_filter | 原检索顺序 | 有 | 有 |
| llm_rerank_filter | 模型评分降序 | 有 | 有 |
| no_pre_generation_gate | 原检索顺序 | 无 | 无 |

查询计划复用上一轮 80 题的首轮检索表达，另外 12 题单独解析一次。题集是 **60 道复用负例 + 20 道复用正例 + 12 道新编计算正例**，不是独立真实流量留出集。标准答案和知识点相关性标签不传入模型。首次预检查发现两道正方形周长题应对应包含周长公式的 `square-area` 知识卡，已在执行任何对照组前修正标签；保留 [标签审计](../data/v4/rerank_ablation/label_audit.json) 和 v1 准备快照，正式结果为 v2。

本次评分提示词只做相关性评分，不同时作全局可回答判断。门控每次只评估最终选入的上下文，避免将整个候选池的覆盖结论直接用于裁剪后的上下文。旧 V4 的耦合评分流程保留在 `workflow.py` 及历史结果中，本实验比较的是解耦后的四种策略，不能直接与旧版 18/20 计算净提升。

所有对照组关闭重检（max_retries=0），隔离首次上下文选择效果。相同模型请求体共享原始 API 响应缓存，减少重复费用，也避免相同上下文重复生成时随机变化；不同上下文仍只有一次模型输出，不能把小幅差异视为稳定统计结论。

完成指 answered / exercises_found；不是独立人工标注的逐句正确率。额外由本助手阅读 77 个不同的已完成正例响应，复核核心计算、题目标签及总结覆盖，没有发现核心结果错误，见 [答案审计](../data/v4/rerank_ablation/v2/answer_audit.json)。该复核不是独立人工测试，也不证明所有句子和引用均正确。

名义调用/token 表示各策略独立运行的模型用量，不含五组共享的查询解析及检索准备。共享缓存后总计保存 345 次不同的 API 响应（含 12 次新增题的查询解析），实际用量 323,825 tokens。报告内耗时为原始 API 时长的回放求和，排除了共同的解析、BGE 及数据库耗时，不能当作实际 HTTP 延迟。

### 重排的额外收益

单独重排相对原顺序多完成 `pos-12`（人民币减法）与 `fresh-05`（8 组各 9 人），但丢失 `pos-13`（14:20 加 40 分钟），净增 **1/32 = 3.125 个百分点**。丢失案例是生成后核验过严，错误地要求来源重复用户数值；失败记录保留。

按预先指定的知识点/年级/题型标签计算上下文 nDCG：原顺序 **0.7428**，单独重排 **0.8940**，提高 **0.1511（相对约 20.35%）**。这是 30 道非总结正例的知识点相关性代理指标；知识卡相关性记 2，同主题例题记 1，并非逐条人工标注的解释充分性。

过滤后再重排，相对只过滤，完成数增量 **0/32**，nDCG 从 **0.6948** 到 **0.7542**，增加 **0.0595**；调用同为 142 次。因为过滤已经需要评分，继续按现有分数排序只增加本地排序，不再增加一次评分调用。因此最终保留重排。

过滤会移除部分同主题例题，按全部相关片段计算的 nDCG 和 precision 可能下降，但上下文中的干扰也减少。不能把过滤后的 nDCG 与未过滤组简单解读为整体问答退步。

### 过滤与门控的作用

重排 + 过滤相对原顺序，正例完成数 **29 → 32**，提高 **9.375 个百分点**，名义调用增加 35 次、tokens 增加约 30.1%。三道恢复案例为人民币减法、分组乘法、乘加两步题。仅过滤也恢复这三题，因此不能把这 3 题全部归因于重排顺序。

原顺序门控组对负例 **34 次拒答、26 次澄清**；10 道缺输入题均给出澄清，但这 10 题由共同的查询预检查处理，不能归功于后续门控。关闭生成前门控后，19 道负例进入了答案生成阶段，门控组则为 0。

冻结的负例指标按状态统计，关闭门控组的 2/60 需结合语义审计理解：

- 银行卡余额问题：正文正确拒绝编造，只是被标为 answered；这是状态误标，并非编造余额。
- 要求题目作者身份证号码：错误地展示了三道真实练习题。这是任务路由失败，没有编造身份证号码。找题路线不经过答案生成后核验，生成前门控因此有独立作用。

所以本实验支持“门控减少误放行和无依据生成尝试”，**不支持“事实幻觉率从 3.33% 降到 0%”的表述**。保留门控四组均为 0/60，满足本回归样本内 ≤5% 的状态口径目标，不能推广为生产保证。

0.75 是继承的启发阈值，本次只验证启用与关闭的差异，没有扫描阈值，也没有证明它最优或经过概率校准。必要要求覆盖仍需 100%，总结目录覆盖至少 90%。

## 代码与接入

- `src/edu_rag/gating.py`：上下文选择与独立证据门控；保留四种内部实验策略。
- `src/edu_rag/deployment.py`：生产策略选择为 `llm_rerank_filter`。
- `src/edu_rag/main.py`：V4 API 接入新流程；V1—V3 路由保留。
- `scripts/evaluate_rerank_gate.py`：冻结输入、共享请求缓存、五组逐题实验。
- `scripts/report_rerank_gate.py`：离线配对分析与待复核答案清单。
- `scripts/verify_gate_live.py`：重新查询理解、真实只读检索及最多两次重检的集成检查。

实际图路径为 `understand → retrieve → select_context → gate → generate → verify → finish`；资料不足时可 `gate → rewrite → retrieve`，最多重检两次。缺必要用户输入时澄清，重检仍缺知识或出处时拒答。记录每轮候选顺序、分数和原文摘录、选入片段、要求覆盖缺口、决策原因、重检次数和引用来源。

没有新增数据库迁移或向量生成。只读查询前后语料指纹保持 `22a72e916102416a0fb9f0f205e6ac2f1c73657adc75f3a788aa2b75c9620a6e`。

另做 8 项生产策略集成检查，使用新解析及 max_retries=2，正例完成、缺宽澄清、未知出处拒答、两次重检上限、过滤条件不变及语料不变检查全部通过，原始响应见 [集成结果](../data/v4/rerank_ablation/live_integration.json)。全项目 143 项自动测试通过。
