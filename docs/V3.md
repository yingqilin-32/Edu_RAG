# V3：Dense + BM25 + RRF 混合检索

代码版本 0.3.0。默认检索升级为混合模式，保留 `dense`、`bm25` 单路模式作为对照。沿用 V2 的课程范围过滤、原始向量、资料引用及 DeepSeek 问答。

## 代码入口

| 文件 | 职责 |
| --- | --- |
| `src/edu_rag/embedding.py` | BGE-M3 本地编码，`return_dense=True`，1024 维向量 |
| `src/edu_rag/rag.py` | `SearchRequest`、`search()`：绑定范围、数据库取候选、调用排名、最后编号引用；`ask()` 接问答 |
| `src/edu_rag/retrieval.py` | 中文词项处理、BM25 计算、`rrf_fuse()`、`rank_candidates()` 与候选轨迹 |
| `src/edu_rag/scope.py` | 两路共用的课程、年级、教材、学期、科目、课程体系过滤 |
| `scripts/verify_v3.py` | 固定语料与问题，真实数据库只读对照，保存配置、分数、排名与指纹 |

原先确实只使用 BGE-M3 的 Dense 输出；现在仍保留该输出。新增的是本地 BM25 关键词分支，没有新增 BGE-M3 的学习型 sparse 向量或 ColBERT 向量。

## 排名过程

1. 根据课程 ID、年级、教材版本、学期、科目、课程体系及可选知识点筛选资料；条件是交集。只允许已向量化且模型指纹一致的片段进入本次比较。
2. Dense 根据问题的真实 BGE-M3 向量计算余弦相似度，取前 `candidate_k=20`。
3. BM25 对相同范围的完整合格语料统计词频、文档频率与长度，取正分数前 20。索引文本是片段正文、资料标题/题号及知识点标题，不包含数据库中另存的参考答案、解析。
4. 两路按片段 ID 去重，以等权 RRF 融合，返回前 `top_k=5`；相同文档的不同片段仍分别保留。
5. 选中之后才附加结构化练习答案、解析，并按最终结果顺序生成 `[C1]` 等引用编号。

```text
RRF(chunk) = Σ 1 / (60 + rank_branch(chunk))
```

排名从 1 开始；没有进入某一路候选的片段，该路贡献为 0。不会直接相加 Dense 余弦与 BM25 原始分数。融合分数相同后，依次比较命中分支数、最好分支排名与片段 ID，确保结果可复现。分数不表示答案置信度。

BM25 使用 `k1=1.2`、`b=0.75`，正 IDF 为 `ln(1+(N-df+0.5)/(df+0.5))`，查询重复词只计算一次。词项经过 NFKC 和大小写归一化；中文使用单字及相邻双字，少量常用字仅从单字项中剔除；数字、小数、包含连接符的完整题号作为词项保留。这是可检查的简单中文词项方案，没有词典分词或同义词扩展。数学运算符本身不作为关键词，因此不能只凭关键词分数判定两道计算题等价。

RRF 思路参见 [Supabase 混合检索说明](https://supabase.com/docs/guides/ai/hybrid-search)，BM25 的 IDF 与参数参见 [Apache Lucene 官方说明](https://lucene.apache.org/core/9_12_1/core/org/apache/lucene/search/similarities/BM25Similarity.html)。本项目的中文词项处理与运行位置是本地实现，并非照搬文档的英文 FTS 示例。

## 使用

在本机已有环境中，无需新服务、依赖包、Key 或数据库迁移，也不用重新生成已有向量。更新包的版本元数据并重启后端：

```powershell
$ragPython = 'D:\Anaconda\envs\edu-rag\python.exe'
& $ragPython -m pip install --no-deps --no-build-isolation -e .
& $ragPython -m uvicorn edu_rag.main:app --host 127.0.0.1 --port 8000
```

打开工作台的“资料问答”，选择检索方式，然后点“仅检索”，可检查排名、分数和两路候选；无需调用 DeepSeek。“查资料并回答”才会使用已有 DeepSeek 配置生成答案。切换范围或检索方式时会清除旧结果，并丢弃尚未返回的旧请求结果。

API 使用 `POST /api/v3/search` 或 `/api/v3/ask`。原 `/api/v1`、`/api/v2` 地址保留为同一实现的别名，**它们的默认模式也变为 hybrid**；需要复现历史排名时显式传 `retrieval_mode: "dense"`。旧版 `python -m edu_rag.evaluate` 已显式固定三年级课程及 Dense，避免新增一年级资料和新默认模式改变历史基线的含义。

示例：

```json
{
  "question": "长方形长8厘米、宽3厘米，周长和面积分别是多少？",
  "course_id": "10000000-0000-4000-8000-000000000001",
  "grade": 3,
  "textbook_edition": "自编演示资料",
  "semester": "full_year",
  "retrieval_mode": "hybrid",
  "candidate_k": 20,
  "rrf_k": 60,
  "top_k": 5
}
```

每个 `source` 返回 `similarity`、`dense_rank`、`bm25_rank`、`bm25_score`、`rrf_score`；没有计算或没有命中的值为 `null`。`retrieval` 返回模式、参数、词项版本、候选列表和分阶段耗时。BM25 模式不计算问题向量，余弦值为空，仍按已有向量的模型指纹限制语料范围。

## 规模与边界

当前 114 个片段适合进行精确扫描。为避免中文关键词索引需要额外服务，本版按请求在 Python 内重建范围内的 BM25 统计；Dense 距离仍由 PostgreSQL/pgvector 计算。混合模式通过同一次 SELECT 获得同一批合格片段，并在本地选择两路候选。

`.env` 可选配置 `BM25_MAX_DOCUMENTS=5000`，默认已生效。范围内超过上限时明确报错，要求缩小范围或设计数据库关键词索引，不能截取前 5000 条后伪装完整检索。该实现适合当前小型知识库，尚未做大语料、高并发负载验收。

Dense 单路沿用原数据库距离排序和 LIMIT，检索结果没有 BM25 上限限制；也不会因为 Dense 的前 20 个结果而限制 BM25 的语料统计。没有匹配课程时返回空结果，禁止回退到其他年级或教材。BM25 词项完全不重合时也返回空结果。

这次只改变检索与记录方式，不写入或改写云端知识、向量及表结构。离线评测文件保存在 Git 项目内。混合检索本身不等于相关性门控：范围匹配但问题超出知识库时，Dense 仍可能返回低相关片段，问答继续依赖证据约束；专门的门控和重排可另行评测。

## 复现与记录

```powershell
& $ragPython -m pytest -q -p no:cacheprovider
& $ragPython -B scripts/verify_v3.py --output data/v3/retrieval_report.json
```

脚本不修改数据库、不重新生成库内向量、不调用语言模型。先预热本地模型，然后在只读、可重复读事务中用同一批语料比较三种模式；每个问题轮换执行顺序，未缓存问题向量。另与原 V2 的数据库 Dense Top-5 SQL 独立核对，防止基线算法悄然变化。

记录包括：

- `data/v3/eval.json`：首次运行前固定的 39 道开发问题及课程限定的标准标签。
- `data/v3/corpus_manifest.json`：语料 ID、课程归属及正文、向量、元数据、答案的 SHA256；不导出向量数值或凭据。
- `data/v3/retrieval_report.json`：逐题三种模式的 Top-5、全部分支候选、分数、排名、耗时，汇总 Hit@1、Hit@5、MRR@5、提升与退步列表。
- `docs/V3-verification.md`：实测结果与解释。

31 道自然问题按所属课程内的知识点判断相关；8 道题号查询必须命中精确题号。这两组单独统计，避免题号查询的收益掩盖普通知识问答。样本来自已有原创资料，是开发集；不用于宣称大规模泛化效果。耗时只作当前 CPU 和网络环境的单次预热测量，不能当作吞吐或生产性能基准。历史 V1、V2 评测记录保留，不与不同语料规模的旧报表直接作因果比较。
