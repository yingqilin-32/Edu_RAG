# V6 Memory：多轮上下文与成本对照

版本0.6.0，2026-10-19。新增本机进程内的 LangGraph 会话记忆，以及无记忆、完整历史、有界结构化记忆三组对照。检索、评分阈值、证据门控和回答生成沿用V5；本版没有引入数学工具、通用工具规划或答案修复循环。

## 实际处理方式

外层 `answer → remember` 图通过 `InMemorySaver` 按会话保存状态。追问首先按当前用户明确的条件还原为可独立检索的问题，再调用原来的V5图。还原只允许使用先前用户题干或工作流已通过核验的回答中的数字，不能把历史回答变成知识库来源。缺少条件时澄清；明确换年级或学期时，清除不再适用的继承课程，当前API明确给定的范围仍优先。

记忆模式：

| 模式 | 行为 |
| --- | --- |
| none | 不向解析/检索提供历史或继承范围；用于无记忆对照 |
| history | 提供本会话完整用户记录和通过工作流核验的回答，最多12次请求 |
| structured | 提供最近4条结构化任务记录及当前范围；默认模式；不是LLM生成的叙述摘要 |

结构化记录保留原题、还原后的题、状态、已通过工作流核验的回答和题目ID/题干。用户的待澄清条件可以保留，失败模型草稿不作为事实保留。数字检查只是防止新数字的最低保护，不证明对象、单位或全部语义条件正确；这些仍须经检索、门控、最终核验和离线评估。

首次没有历史时，三种模式送入V5的请求完全一致。Memory还原、查询解析、重排、门控、生成及核验共享默认10次模型调用、30,000 tokens、90秒预算，仍最多2次重检、每次最多3个分支。超额停止，不能让Memory额外开启一套预算。

## 使用

刷新本机学习工作台，选择“V6 · 会话记忆”。可先问“长方形长8厘米、宽3厘米，周长是多少？”，接着问“那面积呢？”，再问“把长改成10厘米，宽不变，面积是多少？”。页面显示当前轮次和用于检索的完整问题，并能切换完整对话、精简记忆或关闭记忆。

“开始新对话”、切换记忆模式或课程筛选会开始新的上下文。“仅检索”读取已有会话，但不提交新的用户/答案记录。当前页面只展示最近一次结果，尚未实现滚动聊天记录界面。

API新增：

- `POST /api/v6/ask`：不传session_id则由服务器新建随机会话；返回 `memory.session_id`。后续传回该ID与相同memory_mode。
- `POST /api/v6/search`：读取记忆后只执行证据流程，不写入对话内容。
- `DELETE /api/v6/sessions/{session_id}`：清空会话及其检查点。

每个请求包含与V5相同的检索及预算参数，额外支持 `session_id` 和 `memory_mode`；不接受客户端提交的任意历史记录。响应包含原始 `question`、`resolved_question` 和 `memory`，轨迹记录上下文长度、是否调用还原、继承范围及成本。

本机进程最多32个会话，每会话最多12次请求，空闲30分钟过期；同会话并发请求返回409，过期/未知ID返回404，达到会话容量返回429。重启后记忆清空。当前没有登录与真实用户归属认证，随机ID只是本机开发中的会话能力凭证；不应直接作为多人生产服务。多进程共享、持久化、跨设备同步与长期用户档案尚未实现。

## 实验设计

固定14段原创开发对话，每组36轮，共108轮；每组有14道可回答追问、3道不可回答追问，以及19轮用于建立上下文。三组使用相同的语料、模型、V5代码、阈值和预算，仅改变记忆表示。此前单轮Ragas题集不适合直接测量多轮记忆收益，因此本次建立新题集；两份报告的绝对分数不能直接比较。

测试包含：省略题干、修改一个参数并保留其他参数、补充澄清条件、年级/学期切换、完整新题控制、继承题库标签、未提供图片、未收录教材出处和超出结构化窗口后回指旧题。金标准与参考答案不传入被测系统。

记录以下指标：

- 追问作答数量、已列关键条件与来源范围检查；这是粗粒度检查，不等于数学正确率。
- 独立保存的完整用户对话作为Ragas裁判问题，计算答案与参考的匹配分。裁判不把系统还原的题当作金标准；未回答正例另按0计效用。
- 严格追问成功：状态正确、已列条件/范围检查通过且Ragas匹配=1；找题由实际标签和数量检查替代LLM判分。该指标仍非独立人工标注准确率。
- Memory还原、全流程及追问部分的模型调用、输入/输出tokens、上下文字符、预算停止和费用估算。
- 提供商原始API耗时之和作为缓存配对时的耗时代理；真实HTTP端到端冒烟另记录，不混称生产延迟。

负例每组仅3道，不能据0/3声称错误作答率已经满足生产≤5%目标。生成和裁判同为DeepSeek、同一请求使用精确缓存，存在同家族偏差及样本关联；后续需增加独立问题、人工标注和长期历史污染测试。

## 本次结果

| 指标 | 无记忆 | 完整历史 | 最近4条结构化记录 |
| --- | ---: | ---: | ---: |
| 可回答追问完成 | 3/14 | 14/14 | 13/14 |
| 全部36轮tokens | 152,731 | 170,275 | 164,081 |
| 17个追问的模型调用 | 29 | 80 | 74 |
| 17个追问的tokens | 52,563 | 74,158 | 67,964 |
| 已答数学题Ragas匹配分 | 1.0，n=3 | 1.0，n=13 | 1.0，n=12 |

完整历史多完成11道追问，全程tokens增加约11.5%；结构化模式多完成10道，全程tokens增加约7.4%。结构化模式遗漏long-history一题，因为最初原题已离开4条记录窗口，返回明确澄清。这一小型开发集支持短会话优先使用“完整对话”，但不证明任意长期历史都会提升效果。

短对话中结构化记录的字段开销使平均上下文498字符，高于完整历史的408.6字符。它总tokens更少的一部分原因是省去了旧题回指的还原、检索和回答，因此尚无同质量压缩收益的证据。今后如要实现长期摘要，应另测原题可回取、事实保留及历史错误传播。

184项自动测试、8项真实HTTP检查通过。独立只读事务确认数据库指纹不变；裁判额外32次调用、25,210 tokens单独记录，不混入上表应用成本。逐题助手复核见 [答案审计](../data/v6/runs/v2/answer_audit.json)。
