# V2：清洗、切分与课程范围过滤

代码版本 0.2.0。V2 保留 V1 的精确余弦检索和引用问答；数据库已有所需课程字段，复用原表、RLS 和索引，不需要新的迁移或重跑 bootstrap。

## 清洗与切分

- 使用 NFC 归一化，处理 BOM、零宽空格、软连字符、换行和不换行空格；保留乘除号、分数和其他数学符号。
- `boilerplate_lines` 是每个知识点可选的显式页眉页脚列表。只有使用 `\f` 分页时，才移除页首或页尾独立的页码。不会凭词频删除可能属于正文的重复知识。
- 删除相邻且完全相同的普通段落；不同章节中的重复说明、公式、表格、代码均保留。
- Markdown 标题、段落和分页参与切分。每片带知识点标题及章节路径；按实际 BGE-M3 tokenizer 计算完整片段长度，包含特殊 token。默认上限 448 token，不超过环境中的 `EMBEDDING_MAX_LENGTH`。
- 优先按整段、整句切分；单句过长才按字符细分。只允许在容量足够时重叠最后一个短的完整普通段落，默认最多 48 token，不跨章节或页面。
- 公式块、表格、代码和标记为例题的块保持完整；单块过长会明确报错，要求先调整源资料。结构化题干与选项作为整体入库，超长题目拒绝导入。编码器也会拒绝超长文本，避免静默截断。
- 记录清洗/切分版本、原文与清洗正文 SHA256、章节、逻辑页号、片段序号及 token 数量；引用返回相应来源和课程归属。

短知识卡不会为了增加片段数而拆开。当前三年级原创知识卡本身很短，所以升级后数据库数量仍可保持 69。长文、分页和噪声处理使用单独的原创验收资料验证。

## 导入

沿用原有环境和本机 `.env`，不需要新增服务或 API Key。在项目根目录运行：

```powershell
$ragPython = 'D:\Anaconda\envs\edu-rag\python.exe'
& $ragPython -m pip install --no-deps --no-build-isolation -e .
& $ragPython -m edu_rag.ingest demo
& $ragPython -m uvicorn edu_rag.main:app --host 127.0.0.1 --port 8000
```

`demo` 更新已有原创样例的处理元数据。正文不变时保留现有向量；正文或切分变化时，仅让相应片段的向量失效并重新生成。单个文档切分变短时清除该文档多余的旧派生片段，稳定片段 ID；不会按整个文件缺失项删除课程、知识点或练习题。删除整份资料仍需明确的数据管理操作。

预览包含噪声、重复段落、分页、公式及表格的示例（不会写数据库）：

```powershell
& $ragPython -m edu_rag.ingest preview --file data/v2/cleaning_example.json --chunk-tokens 120 --overlap-tokens 24
```

导入自己的已授权资料：

```powershell
& $ragPython -m edu_rag.ingest import --file data/my_book.json
```

先用 `preview` 检查，再使用 `import`。`--no-embed` 可仅导入文字；`embed` 可单独补齐向量。当前输入为 UTF-8 JSON 内的正文与 Markdown，不包含 PDF/OCR、图片识别或公式识别。

JSON 格式参考 `data/v2/cleaning_example.json`。顶层 `course_code` 标识一个明确课程范围，`course` 包含标题、课程体系、学段、绝对年级 1—12、科目、学期和非空教材版本；再提供来源 `source_uri`、授权说明和 `topics`。新课程必须提供完整元数据；已有课程的元数据若不一致会拒绝导入，避免把另一年级或教材写到同一课程。原 V1 格式可复用数据库中已有课程归属。

`topics[].content` 现在允许长正文；`topics[].exercises` 继续提供完整题干、答案、解析及可选选项。教材版本应使用明确且一致的版本名称，例如真实的出版社、版次和修订年份；当前演示数据的值是“自编演示资料”，不是任何出版社教材。

## 过滤

页面加入年级、教材版本和学期筛选。知识目录、详情和问答使用相同条件；切换筛选时清空旧答案，忽略之前范围的延迟响应。没有课程时停用问答按钮。

模型请求会同时提供每条来源的年级、科目、教材和学期。解释要求遵循这些元数据，避免继续固定使用 V1 的“三年级”提示。

新增 `/api/v2/courses`、`/api/v2/knowledge-points`、`/api/v2/knowledge-points/{id}`、`/api/v2/search`、`/api/v2/ask`。原 V1 路径保留为兼容入口，使用同一实现。旧 V0 课程列表保留原行为。

目录接口用 query 参数，检索/问答用 JSON 字段：

```json
{
  "question": "长方形长8厘米、宽3厘米，周长和面积分别是多少？",
  "grade": 3,
  "textbook_edition": "自编演示资料",
  "semester": "full_year",
  "subject": "math",
  "top_k": 5
}
```

可同时传 `course_id`、`knowledge_point_id`，以及 `curriculum`。所有条件以 AND 组合；教材版本精确匹配，空字符串不是“全部”，应省略该字段。学期 `first`、`second`、`full_year` 均精确匹配；筛选上学期不会自动包含全年资料。UI 中的“全部”表示不传该条件。

范围条件、模型指纹、知识点条件都在 SQL 的排序和 LIMIT 前生效，不在 top-k 结果上事后过滤。不匹配的教材、矛盾的年级与课程、未知范围均返回空结果；问答跳过 DeepSeek，不自动放宽筛选。

这些过滤是检索范围控制，不能替代用户授权。当前仍为本机应用，尚无用户登录与公网访问权限设计。

## 验证

```powershell
& $ragPython -m pytest -q -p no:cacheprovider
& $ragPython scripts/verify_v2.py
```

真实集成验收会更新现有样例元数据、验证重复导入和向量保留，再在一个最终回滚的事务中创建四组跨年级、教材、学期资料并生成真实向量。检查预过滤、课程元数据冲突、空范围不调用模型、长文切分，以及缩短文档后清理旧片段。测试课程不会留在业务库中；验收不调用付费问答模型。

结果写入 `data/v2/integration_report.json` 和 `data/v2/retrieval_report.json`。V1 的原报告保留。检索指标依然来自 16 条接近原文的开发问题，不能代表真实教材上的泛化表现。

V2 尚未引入 BM25/RRF、重排或正式门控；这些继续留给后续版本。

可单独验证一次真实问答（先启动本机服务；明确启用后会产生一次模型费用）：

```powershell
& $ragPython scripts/verify_v2_answer.py --with-llm
```

答案、模型用量及引用范围记录在 `data/v2/answer_report.json`。
