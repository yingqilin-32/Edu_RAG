# V3.2：四类意图工作流与四组对照实验

2026-10-18，版本0.3.2。采用工作流：**查询构建 → 范围筛选 → 选择检索方式 → 组织上下文 → 回答或展示题目**。

## 意图与结构

| 意图 | 行为 |
| --- | --- |
| `knowledge_qa` | 确定课程与主题，检索知识卡，生成带引用的解释 |
| `knowledge_summary` | 年级、课程、章节或知识专题总结；按目录选择片段，记录覆盖和遗漏 |
| `exercise_search` | 按题库标签过滤，使用所选检索方式排序；展示存储的题干、选项，答案和解析折叠显示；不调用回答模型编造题目 |
| `problem_solving` | 保留完整题干，召回知识讲解和例题，再生成解答；题目总结使用此意图的 `exercise_task=summarize` 子任务 |

题目总结不进入年级或章节知识总结。缺少题干的“这道方程题怎么解？”需要澄清。解题候选中同时存在知识卡和例题、且预算至少2条时，会各保留最佳的一条，再按排名补充其他上下文。

查询构建草稿支持用户要求的结构：

```json
{
  "intent": "exercise_search",
  "search_text": "一元二次方程 计算题",
  "filters": {
    "subject": "math",
    "grade": 9,
    "knowledge_point": "一元二次方程",
    "question_type": "calculation",
    "difficulty": "medium"
  },
  "limit": 5,
  "needs_clarification": false
}
```

DeepSeek输出此类JSON，Pydantic校验后由后端转换成固定SQL的绑定参数。实际执行计划还记录有效范围、解析来源、主题ID、分支检索文本和用量。不会把模型输出当成SQL执行。

题型支持 calculation、short_answer、fill_blank、single_choice、multiple_choice。难度映射在实验前固定为 easy=1—2、medium=3、hard=4—5，显式“难度2”支持精确匹配2级。没有匹配题时不降低难度、替换题型或跨教材补齐。数量仍受请求的 `top_k` 上限约束。

章节通过知识点 `parent_id` 层级解析，可包含多级子章节；没有注册的章节返回 `no_matching_chapter`，不会把若干相似知识点包装成真实教材章节。年级总览可包含筛选范围内的多门课程，页面新增“使用当前筛选下的全部课程”，勾选后仍保留年级、教材和学期过滤。

## 语料和固定条件

此次没有增加、删除或修改知识库内容：3门课程、31个知识点、81道题、114个真实1024维向量片段。

- 难度1有64题，难度2有17题，难度3—5没有题。
- 计算题55道、填空题4道、简答题22道，没有单选、多选题。
- 知识点当前为平级结构，没有已注册章节，初三一元二次方程也未收录。因此中等/困难、选择题和章节请求只验证空结果；章节树遍历另有单元测试，没有正向真实章节总结效果数据。

评测开始前固定51道开发问题和标准标签：36道检索问题（12知识问答、16找题、8解题/题目总结），6道总结，9道空结果或澄清问题。标准标签来自明确的课程、知识点、资料类型、题型、难度或精确题号，独立于模型输出。

四组为原始BM25、原始混合检索、查询构建+BM25、查询构建+混合检索。原始两组使用完整原问题；查询构建两组共享同一份已缓存的DeepSeek计划。四组具有相同的调用方课程范围，只有查询构建两组增加从自然语言提取的主题和题库标签。所有查询在同一只读、可重复读快照下比较，结束后重新计算数据库指纹确认未变化。

检索问题固定Top-5、每路候选20、RRF k=60，使用同一BGE-M3指纹。总结单独统计，四组一律最多10个来源，避免通过只增加来源数量夸大收益。查询构建两组的知识总结使用目录路径，不执行Dense，因此不能把总结改善归因于Dense。

## 36道检索问题：真实结果

| 实验 | Hit@5 | MRR@5 | nDCG@5 | P@5 | 实际返回结果相关率 | Recall@5 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 原始BM25 | 100% | 0.7778 | 0.7916 | 32.22% | 32.59% | 91.04% |
| 原始混合检索 | 91.67% | 0.7106 | 0.7272 | 29.44% | 29.44% | 82.70% |
| 查询构建+BM25 | 100% | 1.0000 | 0.9899 | 36.11% | 98.33% | 97.10% |
| 查询构建+混合检索 | 100% | 1.0000 | 0.9899 | 36.11% | 98.33% | 97.10% |

相较当前较强的原始BM25，加入查询构建后 nDCG@5增加0.1983、MRR@5增加0.2222、P@5增加3.89个百分点、Recall@5增加6.06个百分点。36道问题按nDCG@5成对比较，18道提升、18道持平，没有退步。

相较原始混合，查询构建+混合有19道提升、17道持平，没有退步。查询构建后的BM25与混合在全部36道的这些二元相关性指标上相同，**没有测得额外Dense收益**。其中30道最终来源ID及顺序完全相同，其余6道虽有来源或顺序变化，但相关性指标没有提高。

指标解释：

- 标准P@5固定以5为分母，库里只有1—2条符合条件也不补无关结果，所以此项不能达到100%。
- 实际返回相关率以实际返回条数为分母，空返回在正例中记0。98.33%的高值有一部分来自过滤和减少无关输出，不能仅凭此值认为系统能回答98.33%的问题。
- nDCG@5使用二元相关标签，按前5条折损排序；MRR@5是首个相关结果的排名倒数，五名外记0。
- Recall@5按所有标注相关片段计数。同一主题存在多份知识卡及例题，前5条不一定能取全；它也不代表解题必须阅读全部相关片段。
- 表格均为按问题宏平均。相关性由课程与主题/类型/题库标签约束定义，是可复核的检索代理指标，不是完整人工语义判分或生成答案正确率。知识问答要求解释型知识卡，找题要求匹配题库标签，解题允许知识卡和例题。

| 原始BM25 | 0.8698 | 0.6887 | 0.8803 |

主要收益是选对资料类型和题库条件，以及让首个正确结果排在前面。它包含查询构建、确定性过滤、意图路由及上下文组织的共同作用，不能全部归因于语义改写，也不能把该实验解释成“纯LLM分类器”效果。

## 总结和空结果另外统计

6道总结的已收录知识点覆盖率，四组均使用10个来源预算：

| 实验 | 知识点覆盖率宏平均 | 上下文相关率 |
| --- | ---: | ---: |
| 原始BM25 | 85.00% | 63.33% |
| 原始混合检索 | 77.64% | 51.67% |
| 查询构建+BM25 | 88.19% | 100% |
| 查询构建+混合检索 | 88.19% | 100% |

例如三年级总览：相同10条来源预算下，原始BM25覆盖8/16个知识点，原始混合覆盖4/16，目录路径覆盖10/16。不是本次数据只有10个知识点，而是比较实验限额为10；正常工作台默认概览预算20，可覆盖已收录16/16。已收录范围不等于完整教材。

9个空结果或澄清场景：两种原始检索均返回了片段，查询构建两组均正确停止或澄清，正确处理9/9。此项只衡量检索阶段，不能据此断言原始回答模型一定会答错或不会拒答。

## 保留的失败案例

`solve01`：“53个人乘船，每条船最多8人，至少要几条船？”

查询构建未把隐含主题解析为有余数除法，主题过滤为空。构建后的两种检索均在Top-5中返回2条有余数除法资料，同时混入乘法口诀和分类统计资料；该题返回相关率40%、nDCG@5=0.6367。模型能找到核心片段，仍有隐含主题识别和噪声控制问题。没有根据此结果修改规则后重跑指标。

## 时间、用量与验证

| 实验 | 检索函数耗时中位数 | 加入本次解析耗时后的请求估计 |
| --- | ---: | ---: |
| 原始BM25 | 146ms | 146ms |
| 原始混合检索 | 535ms | 535ms |
| 查询构建+BM25 | 75ms | 1640ms |
| 查询构建+混合检索 | 447ms | 2049ms |

过滤后候选少，排名本身更快，但DeepSeek查询解析使总耗时增加。后两组的约409ms差额来自额外向量检索路径，没有换来已测指标提升。以上是预热CPU、数据库网络环境下单次执行的函数测量，轮换执行顺序，不含HTTP传输/JSON编解码，不是生产并发基准。查询计划在实验中只调用一次，但给两种检索的请求耗时估计各加上同一份实测解析时间，避免把缓存解析伪装成免费。

实际完成50次DeepSeek查询构建，另外1个缺少题干的问题由规则直接要求澄清；无模型失败回退。51道的最终意图均符合开发标签，未触发意图纠正守卫。查询构建用量83536 tokens，另外一次真实解题1140 tokens，总84676 tokens，共51次实际API调用。真实解题得到周长22厘米、面积24平方厘米，并附带引用；这一个样例不计为答案准确率评测。

98项自动测试通过，另有真实数据库题型/难度过滤及不调用回答模型的题库展示预检。数据库数据及标签前后指纹均为 `a339528b8dc21f20dcae98d7103ea7c06fe41b33c52aecf9ba13b9f8bb709946`。

当前证据支持以“查询构建+BM25”作为本知识库的优先检索配置，保留混合模式继续对照。所有问题来自少量已有原创资料，类型与标签较干净，没有独立保留集，不能推广为Dense对其他语料无用，也不能宣称生成答案准确率提高到99%。没有中高难度、真实章节、真实用户分布的正例验证。

页面默认选择BM25和免费本地解析，API的检索默认值仍为hybrid以保持兼容。本表使用的是实际DeepSeek解析，其效果与耗时不能直接套用到免费规则模式。此前V3.1的39题报告采用不同问题集和相关性口径，只保留为历史记录，不与本次51题直接计算提升。

页面验收使用免费本地解析：三年级“难度2、长方形面积计算题、5道”展示2道匹配原题并提示数量不足，答案和解析可展开；“中等难度”返回0条，没有降低难度补齐；一年级全年总览勾选全部课程后，跨上下学期提供15/15个已收录知识点。此验收与上面的DeepSeek四组实验分开记录，不并入评测指标。

## 记录与复现

- `data/v3/four_way/eval.json`：首次打分前固定的51个问题及标准标签。
- `data/v3/four_way/plans_deepseek.json`：逐题原始解析来源、校验后计划、时延、用量。BM25/混合复用同一份计划。
- `data/v3/four_way/corpus_inventory.json`：实验语料的课程、知识点、题型、难度等记录。
- `data/v3/four_way/report_deepseek.json`：每题四组来源、分支候选、分数、指标、覆盖率、差异和实际解题结果；包含问题集、代码、提示词与数据SHA256。
- `scripts/evaluate_four_way.py`：只读预检、模型计划缓存与四组计算。指标公式另用手算示例验证。

```powershell
$ragPython = 'D:\Anaconda\envs\edu-rag\python.exe'
& $ragPython -B scripts/evaluate_four_way.py --preflight-only
& $ragPython -B scripts/evaluate_four_way.py
```

第二条在代码、模型配置、问题和语料指纹相同且已有缓存时，复用已存计划，不再次调用查询模型；首次无缓存时会调用模型。`--with-answer-check` 会另外增加一次真实回答调用。脚本检测到缓存指纹不一致会停止，要求保留旧实验并另建版本。`--plan-mode rules` 可做独立的免费规则计划实验，不与本表的DeepSeek主实验混用。
