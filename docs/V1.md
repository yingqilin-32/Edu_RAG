# V1：看见知识库，跑通有依据的回答

## 数据够不够

V0 的 2 个知识点、3 道题和 5 个空向量片段只验证数据库与环境。它们不足以代表三年级知识范围，也不足以证明检索优化有效。

V1 新增 16 张原创知识卡和 48 道练习题，并复用 V0 课程与两个已有知识点。初始化后的总数：

| 内容 | 数量 |
| --- | ---: |
| 课程 | 1 |
| 知识点 | 16 |
| 原创资料 | 17 |
| 练习题 | 51 |
| 题目与知识点关联 | 51 |
| 检索片段 | 69 |
| 真实向量 | 69 |

知识范围包括四位数、三位数加减、乘法、除法、单位换算、经过时间、周长、面积、分数、小数钱数和简单统计。内容为本项目原创演示资料，含部分基础复习内容，不承诺对应某个教材版本或覆盖完整课标。

这些数据适合检验入库、模型隔离、检索、引用和页面。后续比较 V2—V6 时，应补充授权教材、容易混淆的问题、资料不足问题，以及独立的人工核验测试集。

## 知识在哪里

- `edu_knowledge_points`：知识点标题、学习目标和课程归属。
- `edu_documents`：资料名称、来源和授权说明。
- `edu_chunks`：真正用于检索的正文及向量；向量本身不是人可读的知识正文。
- `edu_exercises`：题干、答案和解析；题目向量只编码题干，召回后通过同一次关联查询补入对应标准答案与解析，供学习展示和模型回答使用。

浏览入口是 `http://127.0.0.1:8000/`。知识目录通过结构化查询完整列出当前已收录知识点；问答只召回最相近的片段，两者范围不同。

可直接阅读 `data/v1/math_g3.md`。程序导入 `data/v1/math_g3.json`，每张知识卡作为一个完整片段，当前样例均适合 512 token 的编码配置；题干单独作为片段。V1 暂不包含 PDF/OCR 或通用长文档切分。

## 运行

继续使用现有 `edu-rag` Conda 环境。PowerShell 无需依赖激活脚本：

```powershell
Set-Location 'D:\2026-2027telecom_sudparis\Edu_RAG\Edu_RAG_V0'
$ragPython = 'D:\Anaconda\envs\edu-rag\python.exe'
& $ragPython -m pip install -r requirements-rag-lock.txt
& $ragPython -m pip install --no-deps -e .
& $ragPython -m edu_rag.ingest demo
& $ragPython -m uvicorn edu_rag.main:app --host 127.0.0.1 --port 8000
```

重复执行 `ingest demo` 会复用稳定记录，不重复新增相同样例。更改正文后，原向量会清空并重新计算；已生成且模型标识一致的向量会跳过。单独重建缺失或不同配置的向量：

```powershell
& $ragPython -m edu_rag.ingest embed
```

只导入文字、不运行模型：`& $ragPython -m edu_rag.ingest demo --no-embed`。

数据库 schema 继续使用原 V0 迁移；升级不需要重新运行 `bootstrap_v0.sql`。

## 配置

密钥与数据库密码保存在本机 `.env`，不发送到浏览器：

```dotenv
EMBEDDING_MODEL=BAAI/bge-m3
EMBEDDING_DEVICE=cpu
EMBEDDING_MAX_LENGTH=512
DEEPSEEK_API_KEY='本机实际密钥'
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-flash
DEEPSEEK_TIMEOUT=45
```

编码器采用已下载的本机权重，CPU/FP32、L2 归一化。向量标识包含模型仓库名、缓存 revision 和编码长度。入库与查询使用相同标识；修改编码长度或权重后需重新执行 `embed`，避免混用向量空间。模型加载在进程内缓存，更改 `.env` 后重启后端。

V1 使用 DeepSeek 非思考模式，每次生成最多 1024 个输出 token，不自动重试计费请求。缺少可检索片段时不会调用生成模型。API 密钥无效、余额不足、限流和网络失败均以可读错误返回。

## API

| 接口 | 用途 |
| --- | --- |
| `GET /` | 本机知识浏览与问答页面 |
| `GET /api/v1/courses` | 课程及实际数据数量 |
| `GET /api/v1/knowledge-points?course_id=...` | 课程知识目录 |
| `GET /api/v1/knowledge-points/{id}` | 学习目标、知识正文、练习和解析 |
| `POST /api/v1/search` | 精确余弦向量检索，无模型 API 费用 |
| `POST /api/v1/ask` | 检索、拼接上下文、DeepSeek 回答与引用 |

查询体示例：

```json
{"question":"长方形长8厘米、宽3厘米，周长和面积分别是多少？","top_k":5}
```

可选 `course_id` 和 `knowledge_point_id` 均为数据库 UUID。`top_k` 为 1—10。保留 V0 的 `/api/v0/courses` 和健康检查接口。

## 引用与边界

每次检索结果分配 C1、C2 等临时引用编号。答案中的编号必须对应本次召回的真实片段；不存在的编号被拒绝，没有引用的答案不会标记为有据回答。界面显示原文，便于人工核对。

这只验证引用定位，不证明每一句话都能被资料支持，也不保证所有计算正确。V1 用提示词要求资料不足时说明情况；正式门控阈值、混合检索、重排与多轮编排尚未加入。

## 验证与基线

```powershell
& $ragPython -m pytest -q
& $ragPython -m edu_rag.evaluate
```

`data/v1/eval.json` 包含 16 条库内开发问题和 2 条库外问题。检索基线只统计 16 条库内问题的知识点命中率@5 和 MRR@5，写入 `data/v1/retrieval_report.json`。它不是独立测试集，不能据此宣称对真实用户问题有同样表现。库外问题的回答和拒答另做端到端检查。

运行记录见 `docs/V1-verification.md`。
