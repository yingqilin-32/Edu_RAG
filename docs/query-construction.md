# V3.1：意图分类与查询构建

版本 0.3.1。在已有混合检索前增加可检查的查询计划：把用户自然语言拆成意图、语义检索文本、关键词、元数据条件，再由后端执行固定的参数化 SQL。

设计参考用户提供的 [All-in-RAG 查询构建章节](https://github.com/yingqilin-32/all-in-rag/blob/main/docs/chapter4/12_query_construction.md)。本项目采用其中的“查询文本 + 元数据过滤”思路，用现有 Pydantic 与 PostgreSQL 实现。该章中 limit=1 并不能实现“时间最短”的例子，也说明数量限制与排序语义需要区分：本版 `limit` 只表示题目返回数量，没有按难度、时间排序或任意聚合查询能力。

## 三种意图与执行路径

| 用户表达 | 意图 | 执行方式 |
| --- | --- | --- |
| 总结一年级下学期数学有哪些知识点 | `summary`，课程概览 | 从限定课程的知识目录收集知识卡，每个知识点一个片段，记录覆盖与遗漏 |
| 梳理长方形周长和面积的公式 | `summary`，专题总结 | 限定知识卡和已解析的主题，进行 Dense + BM25 + RRF |
| 找3道一年级下学期人民币练习题 | `exercise` | 年级1、下学期、人民币主题、题目类型过滤后检索，最多返回请求题数 |
| 请查找题号 V1-TIME-DURATION-002 的题目 | `exercise` | 完整题号作为等值条件，不用相似题替代 |
| 什么是单位分数 | `knowledge` | 普通知识问答兜底，知识卡和练习都可作为依据 |

总结这道具体题的解题方法仍属于题目类，避免丢失题干。缺少题干的“讲解这道题”会要求补充信息；目前不维护多轮对话上下文。

课程概览与专题总结分别处理。概览不使用相似度 Top-5 代表整个课程，而按知识目录选择片段；专题总结继续使用混合检索。概览也不代表教材完整覆盖：默认最多20个来源，可用 `summary_max_sources` 调为1—40，并列出未覆盖的知识点。每个知识点仅取一个片段，长文中的其他片段不因此被视为已经阅读。

## 查询计划与数据库条件

主要字段：

- `intent`：summary、exercise、knowledge。
- `semantic_query`、`bm25_query`：分别送入 Dense 和 BM25；原问题继续用于生成最终回答。
- `extracted_filters`、`effective_scope`：从问题提取的条件及与页面筛选合并后的条件。
- `content_kind`：知识卡、题目或全部。
- `topic_filter`：从当前范围内真实知识点解析的 ID 与标题。当前只支持明确概念词匹配，如人民币、凑十、周长、面积；复杂隐含主题仍依靠检索文本，不宣称任意主题识别能力。
- `exercise_code`：只能复制问题中的完整题号。
- `requested_limit`、`effective_top_k`：明确要求的题数及实际片段上限；实际上限取请求题数与 API `top_k` 的较小值。题目不足时不凑数。
- `strategy`、`coverage`、`warnings`、`origin`：执行路径、覆盖情况、校验修正与解析来源。
- `usage`、`model`：查询解析的用量和模型，独立于最终回答的用量。

允许自然语言提取的课程条件为年级、学期、科目和教材版本。页面课程 ID 与课程体系等既有条件保持有效；条件取交集。课程元数据还用于校验“已选择三年级课程、问题却要求一年级”等冲突，这种情况返回 `needs_clarification`，不执行向量检索或回答生成。没有对应课程或主题时返回明确空结果，不替换为其他教材或年级。

LLM 只生成有严格字段、类型与取值限制的 JSON，不能提供 SQL、表名、操作符或任意数据库命令。数据库访问由 `rag.py` 的固定只读 SELECT 完成。题号、课程范围、知识点 ID 均作为绑定参数；SQL 字符串不拼接模型输出。

数量题保留原问题用于语义检索，以免改写尺寸、单位或算式；关键词同时保留原题。模型改写改变数字或运算符、关键词出现新增数字时，也回到原问题并记录原因。模型漏掉本地已识别的年级、学期、题号等字面条件时，由代码补回；模型与这些条件冲突时要求澄清。程序仍不能证明自然语言解析完全正确，因此页面提供完整计划供核对。

## 使用与费用

页面“资料问答”增加“查询理解”：

- **本地解析 · 免费**：页面默认，用规则识别常见表达，不调用 DeepSeek。
- **DeepSeek 解析 · API**：每次请求最多额外调用一次模型，结构化 JSON 输出经校验后执行。输出无效或调用失败时回退到本地规则，显示原因并保留范围约束。
- **关闭 · 原问题检索**：复现 V3 原有方式。

DeepSeek 解析沿用已有 `.env` 的密钥、模型和地址，采用 [DeepSeek 官方 JSON Output](https://api-docs.deepseek.com/guides/json_mode/) 的 `response_format={"type":"json_object"}`。无需新环境或库内向量重算。模型温度设为0仍不能保证完全确定的结果，所以必须进行结构校验和边界检查。

点击“仅检索”不会生成答案，但选择 DeepSeek 解析时仍会产生查询解析调用。点击“查资料并回答”，正常有证据时再增加一次回答调用。已知空的页面范围会在查询解析调用之前返回；问题解析后才发现的冲突，可能已经发生一次解析调用，但不会继续生成答案。不自动重试 API 请求。

## API 与代码

`POST /api/v3/plan` 可只查看计划，不生成向量或答案。`/api/v3/search` 和 `/api/v3/ask` 执行相应操作。请求示例：

```json
{
  "question": "找3道一年级下学期人民币练习题",
  "grade": 1,
  "semester": "second",
  "query_mode": "deepseek",
  "query_intent": "auto",
  "retrieval_mode": "hybrid",
  "top_k": 5
}
```

`query_mode` 支持 off、rules、deepseek；API 默认 off，保持旧调用和历史基线的含义，页面显式传 rules。`query_intent` 支持 auto、summary、exercise、knowledge，可在启用查询构建时人工指定意图。旧 API 地址同样接受这些字段。

| 文件 | 职责 |
| --- | --- |
| `src/edu_rag/query.py` | 查询草稿类型、本地解析、DeepSeek JSON 提示、字段校验、条件合并及主题解析 |
| `src/edu_rag/rag.py` | `construct_plan()`、参数化检索、课程概览、来源覆盖、按意图组织回答 |
| `src/edu_rag/llm.py` | 查询解析与回答共用的单次 DeepSeek 调用及安全错误处理 |
| `tests/test_query.py` | 分类、条件冲突、数量单位、无效模型输出、回退及覆盖测试 |
| `scripts/verify_query_construction.py` | 真实数据库、旧结果兼容性及可选真实模型调用验收 |

## 2026-10-18 实测

82 项自动测试通过。真实数据库13个功能场景通过，另有10项检查确认关闭查询构建时，5个既有问题的 Dense 与混合结果仍与旧报告一致。验收前后知识库指纹一致，仍为114个片段，无数据库迁移或知识内容写入。

| 场景 | 原问题直接混合检索 | 加入查询构建 |
| --- | --- | --- |
| 三年级课程概览 | 5个片段，覆盖5个知识点 | 16个知识点各选1个片段，覆盖16/16个已收录知识点 |
| 找3道一年级下学期人民币题 | 5个片段，混有知识卡和规律题 | 仅返回2道现有人民币题 |
| 精确题号查询 | 目标题及其他4个片段 | 仅返回目标原题 |
| 概览上限设为3 | 没有课程覆盖统计 | 提供3/16个知识点，明确列出另外13个 |

实际 DeepSeek 验证包含3次查询计划解析和2次回答生成，均成功，共5次 API 调用、服务报告5274 tokens。总结回答覆盖一年级下学期7个已收录主题并引用来源；题目回答得到周长22厘米、面积24平方厘米。该验证是功能样例，不是答案准确率或分类泛化能力基准。

固定问题及预期条件见 `data/v3/query_construction/eval.json`，完整计划、旧版对照、实际回答与用量见 `data/v3/query_construction/report.json`。旧 V3 的检索评测文件保留。

实际浏览器已验收总结类16/16覆盖、题目类人民币主题仅返回2题、JSON计划展开、筛选冲突提示，以及 DeepSeek 解析费用提示。截屏保存在本机 `.runtime/query-summary.png` 和 `.runtime/query-exercise.png`，作为运行附件，不纳入 Git。
